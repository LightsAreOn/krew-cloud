Task Card & Slack Process

This SOP answers one question: how do task cards work in KREW, and how does the team use Slack to coordinate on them? It covers how tasks are created, who can create them, how agents report progress, and how the morning brief keeps the Chairman informed without anyone having to send a separate update.

What a task card is

A task card is a row in the agent_tasks table in the KREW Supabase database. Every piece of work — whether done by an AI agent or a human — is tracked here. The Chairman sees open task cards every morning in the brief. Monica flags overdue cards in her nightly QMS review.

Task card fields

title
One sentence. What is the work? Specific enough to understand without reading the description.
description
Context, success criteria, links to relevant QMS documents, background information.
agent
Who owns this task: ceo · cto · cpo · cmo · cfo · clo · qsm · alf · bruce · donna · petter · chairman
type
AO Agent Order — task for an AI agent  ·  WO Work Order — task for a human  ·  SO System Operation — automated
status
proposed → backlog → this-week → review → done (see lifecycle below)
priority
urgent · high · normal
due_date
Target completion date. Monica flags tasks where due_date has passed and status is not done.
proposed_by
Who raised the task.
approved_by
Who authorised it to proceed.
result
Filled when done: what was produced, where it lives, what the outcome was.
workspace
Always "krew" for KREW tasks.

Status lifecycle

Every task card moves through five states. The move from one state to the next triggers a specific Slack action.

Proposed
Raised but not yet approved. Sits in Decision Queue.
Backlog
Approved. Queued. Not yet started. No Slack needed.
This week
Agent is actively working on it. Slack post required on pickup.
Review
Agent considers it done. Waiting for sign-off. Slack post required.
Done
Verified by CEO or QSM. Result field logged. No Slack needed.

Slack process

All task updates go to #proj-cortex. This is the single channel where the Chairman and CEO have authority to post, and where all agents report task status. Use the exact formats below — consistency is what makes the channel scannable.

When you pick up a task (backlog → this-week)

Format — task pickup
[AO] Louis · CLO · EU AI Act A-001 to A-012 compliance review Status: In progress Approach: Auditing all 12 actions, assigning owners and due dates. CLO leads, CEO accountable. Target: 20.06.2026

When a task is done and ready for review (this-week → review)

Format — ready for review
[AO] Amanda · CPO · P-01 scope revision — KREW TEAM MVP Status: Ready for review Output: P-01 v2 filed in QMS. 10-feature spec confirmed. Multi-user removed from 11.11 scope. Next: CEO review → Chairman approval

When a task is blocked

Format — blocked
[AO] Don · CMO · Publish blog to krew.cloud Status: BLOCKED Blocker: WO-003 — website publish infrastructure is a human task. Chairman action required. Needs: Chairman to enable deploy to LightsAreOn/krew-cloud or confirm website timeline.

WO items (human tasks)

Format — human work order reminder
[WO] Chairman · Azure app registration — Microsoft Graph API Action required by Chairman: 10-minute task in portal.azure.com. Unlocks: full brief automation (email stats + Donna calendar). Guide available from CTO.
Channel discipline
Only task-related status updates in #proj-cortex. Strategy, architecture, and planning discussion go to the relevant agent channel or a direct thread. #proj-cortex stays scannable.

Weekly cadence

Every Monday — Monica reviews all open tasks. Any task stuck in this-week for more than 7 days is escalated to the CEO. Any task past its due_date is logged as a deviation in the QMS.

Every Friday — CEO posts a weekly close to #proj-cortex: what moved to done, what is stuck, what is being added to backlog.

Nightly — Briefer reads all open tasks and includes them in the Chairman's brief. Monica's 00:45 QMS review flags anything overdue.

Slack activity in the brief

The brief will include a SLACK section showing recent activity across channels the Chairman subscribes to. This requires the SLACK_BOT_TOKEN to be added to Supabase Vault.

Current limitations (v1)

This is v1.0 — designed to work with what exists today. No real-time Slack ↔ database sync. Agents post manually on status change. The KREW TEAM Decision Queue (Amanda/CPO scope) will give task cards a proper UI in the product. When that ships, this SOP will be updated to v2.0 reflecting the new interface.
